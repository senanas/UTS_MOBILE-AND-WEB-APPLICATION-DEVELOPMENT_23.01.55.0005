1. Problem Statement

Pemilik toko jam tangan menghadapi tiga masalah utama dalam pengelolaan operasional sehari-hari:

NoMasalahDampak
1Pencatatan stok dan nomor seri yang masih manualRentan duplikasi nomor seri, kesalahan hitung stok, dan kesulitan melacak unit spesifik. Pencarian membutuhkan waktu lama karena data tersebar di buku catatan atau spreadsheet tidak terstruktur.
2Informasi tipe mesin dan spesifikasi tidak terorganisirTipe mesin (Automatic, Quartz, Solar) dan spesifikasi teknis tidak tercatat secara konsisten, sehingga pemilik tidak dapat memfilter atau membandingkan produk dengan cepat.
3Riwayat servis dan pengingat garansi tidak terkelolaPelanggan jam tangan premium mengharapkan layanan purna jual, namun riwayat servis tercatat di tempat terpisah dan tidak ada pengingat otomatis untuk garansi atau servis jatuh tempo.

Ketiga masalah berakar pada satu hal yang sama: pencatatan yang masih manual dan tersebar di banyak tempat. ChronoStore menggabungkan ketiga fungsi — manajemen stok, katalog terorganisir, dan riwayat servis — dalam satu sistem terpusat.

3. User Stories

Berdasarkan analisis masalah dan persona, berikut enam user story utama ChronoStore:

IDPeranUser StoryKriteria Penerimaan
US-01AdminSebagai admin, saya ingin menambah, mengedit, dan menghapus data jam tangan sehingga katalog selalu terbarui.CRUD berfungsi penuh; data baru tampil di daftar; konfirmasi SnackBar muncul.
US-02AdminSebagai admin, saya ingin nomor seri divalidasi secara unik sehingga tidak ada dua jam tangan dengan nomor seri yang sama.Form menolak nomor seri duplikat dengan pesan "Nomor seri sudah digunakan"; saat edit, nomor seri milik jam itu sendiri di-skip.
US-03AdminSebagai admin, saya ingin mencatat riwayat servis per unit jam tangan sehingga layanan purna jual terdokumentasi.Form catat servis menyimpan tanggal, jenis, deskripsi, dan biaya; riwayat tampil di halaman detail.
US-04AdminSebagai admin, saya ingin menerima pengingat garansi dan servis yang mendekati jatuh tempo.Halaman pengingat menampilkan garansi/servis jatuh tempo dalam 7 hari, diurutkan dari terdekat.
US-05PelangganSebagai pelanggan, saya ingin melihat katalog jam tangan dengan filter berdasarkan tipe mesin.Katalog menampilkan semua jam; filter Automatic/Quartz/Solar berfungsi; pencarian nama/merek berfungsi; empty state tampil jika tidak ada hasil.
US-06UmumSebagai pengguna, saya harus login terlebih dahulu sebelum mengakses fitur aplikasi.Email dan password divalidasi; login gagal menampilkan pesan error; login sukses navigasi ke dashboard/katalog sesuai role.

5. User Flow

Alur pengguna dimulai dari login dan bercabang sesuai peran:

  Login → Dashboard (Admin) / Katalog (Pelanggan)

    Admin: Dashboard → Data Jam Tangan → Tambah/Edit (Form) → Detail → Riwayat Servis

    Admin: Dashboard → Pengingat Garansi & Servis

    Pelanggan: Katalog → Detail (read-only) → Pesan → Transaksi

  Logout → kembali ke Login

Setiap transisi menggunakan Navigator.push dan Navigator.pop. Navigasi utama (Dashboard, Data Jam, Pengingat) menggunakan BottomNavigationBar pada layar mobile (lebar < 600px) dan NavigationRail pada layar web/tablet (lebar ≥ 600px).

Relasi Antar Collection

  users (1) → (banyak) transactions

Catatan: Saat ini (fase UTS) data disimpan secara in-memory menggunakan mock data (List di Dart) yang dikelola oleh Provider. Rancangan Firestore di atas akan diimplementasi pada Pertemuan 9-15 menuju UAS. Karena sudah menggunakan Repository Pattern, hanya file di repositories/ yang perlu diubah — layar, provider, dan model tetap sama.
